گزارش آزمون نسخه سبک‌شده Vexta
تاریخ: ۱۴۰۵/۰۸/۲۹ (2026-11-20)

آزمون‌های انجام‌شده در محیط محلی:
- Python compile (py_compile): موفق
- JavaScript syntax (node --check): موفق
- بارگذاری صفحه اصلی از سرور محلی: HTTP 200
- ورود مدیر با رمز اشتباه: HTTP 403 (رد شد)
- ورود مدیر با شماره و رمز معتبر: HTTP 200 (موفق)
- دریافت داشبورد خلاصه مدیر: HTTP 200
- مسیر گزارش مالی مستقل: HTTP 404 (حذف شده)
- مسیر خروجی Excel: HTTP 404 (حذف شده)
- مسیر چت: HTTP 404 (حذف شده)
- دریافت قطعه PDF با HTTP Range: HTTP 206 و Content-Range صحیح
- دسترسی مستقیم به URL فایل PDF: HTTP 403
- پاک‌سازی فایل آموزشی با عمر بیش از ۹۶ ساعت: فایل و رکورد دسترسی حذف شدند
- پاک‌سازی پیوست قدیمی فیش/درخواست کیف پول: داده باینری حذف و رکورد مالی حفظ شد
- تأیید درخواست شارژ کیف پول: موجودی/تراکنش ثبت شد و پیوست رسید از رکورد حذف شد

تغییرات:
- حذف چت مستقل و سوابق پیام‌های آن از دیتابیس محلی هنگام راه‌اندازی نسخه جدید.
- حذف صفحه گزارش مالی مستقل و endpoint آن؛ داشبورد فقط آمار ضروری و درآمد کل را نمایش می‌دهد.
- حذف ورود/خروج Excel و وابستگی openpyxl.
- حذف اعلان‌های مستقل مدیریت؛ اعلان‌های مرتبط با مشتری حفظ شده‌اند.
- حذف PyMuPDF و مسیرهای رندر PDF در سرور؛ PDF.js در مرورگر اجرا می‌شود.
- سرور فایل PDF را با HTTP Range و قطعه‌های ۶۴ کیلوبایتی ارسال می‌کند؛ رندر و جست‌وجوی صفحات سمت مرورگر است.
- واترمارک شناسه/نام مشتری روی صفحه نمایش داده می‌شود؛ دکمه دانلود/چاپ در نمایشگر وجود ندارد.
- داشبورد به‌جای بارگذاری تمام entityها از aggregateهای SQL و فقط ۶ مشتری اخیر استفاده می‌کند.
- ساخت جدول و ایندکس‌ها از هر درخواست حذف و به راه‌اندازی منتقل شده؛ SQLite با WAL و synchronous=NORMAL اجرا می‌شود.
- پاک‌سازی فایل‌های منتشرشده و پیوست‌های مالی پس از ۹۶ ساعت اجرا می‌شود. زمان‌بندی scheduler هر ۶۰ ثانیه بررسی می‌کند؛ پاک‌سازی حداکثر تا چرخه بعدی انجام می‌شود.
- پیوست فیش بلافاصله پس از تأیید از رکورد حذف می‌شود و سابقه مالی باقی می‌ماند.
- ورود مدیر با PBKDF2-SHA256 محافظت می‌شود؛ هش در کد است و با VEXTA_ADMIN_PASSWORD_HASH قابل جایگزینی است.

مواردی که در این محیط آزمون نشدند:
- اجرای واقعی رابط در مرورگر و سازگاری PDF.js با تمام مدل‌های Android/iOS.
- بارگذاری کتابخانه PDF.js و worker از CDN؛ محیط اجرای ما دسترسی شبکه خارجی نداشت. برای استفاده، مرورگر کاربر باید به CDN دسترسی داشته باشد.
- آزمون فشار چندکاربره و اندازه‌گیری واقعی RAM/CPU.
- استقرار اینترنتی، HTTPS، OTP مشتری، CSRF، rate limit عمومی و آزمون نفوذ.

هشدار استقرار:
این پروژه همچنان نمونه محلی است. ورود مشتری هنوز OTP واقعی ندارد، نشست‌ها در حافظه‌اند و سرور HTTP پایه برای اینترنت عمومی سخت‌سازی کامل نشده است. قبل از انتشار عمومی باید احراز هویت مشتری، نشست پایدار/امن، HTTPS، CSRF، محدودیت تلاش ورود، پشتیبان‌گیری و ذخیره‌سازی پایدار تکمیل شوند. عدم نمایش دکمه دانلود به معنی جلوگیری قطعی از استخراج فنی PDF یا اسکرین‌شات نیست.
